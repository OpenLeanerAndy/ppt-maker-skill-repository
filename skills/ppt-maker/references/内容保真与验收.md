# 内容保真与验收规则

## 1. 输入文件解析

- 对用户明确给出的文件名或路径使用字面路径，不使用 Glob 重新猜测文件。
- 解析为绝对路径后，核对文件存在性、扩展名、文件大小；重要任务同时记录 SHA-256。
- 中文、空格、括号、方括号和引号均属于文件名本身，不得改写。
- 找到零个文件时报告实际检查的目录；找到多个候选文件时让用户选择，不得静默选取。
- 不得把文件正文拼接进 Python、JavaScript、PowerShell 或 shell 源代码。正文、表格和路径只能通过 UTF-8 JSON、参数数组或文件传递。

## 2. 源内容清单

读取完整素材后建立 `sourceManifest`。至少记录：

- `sources`：源文件 `id`、字面路径和可选 SHA-256。
- `sections`：源材料全部一级标题的`id`和原始`title`，用于核对目录覆盖。
- `textItems`：必须原样保留的标题、结论、风险、否定表述、数字及正文，包含唯一 `id` 和完整 `text`。
- `tables`：每张源表的唯一 `id`、正文行数、逻辑列数和表头行数。
- `media`：每张必须使用的源图片或图表的唯一 `id` 和本地路径。
- `contentGroups`：按源文档标题层级和连续内容建立的语义组，记录原始顺序、默认单页归属、首选阅读流和允许拆分条件。

默认所有清单条目均为必需项。确需不展示时，写入非空 `omittedReason`，并在大纲确认阶段向用户说明；不得直接删除。

PptxGenJS 输入中的页面、模块或内容块使用 `sourceRef` 或 `sourceRefs` 引用清单条目。表格和图片必须引用各自的源表或源媒体 `id`。

目录项使用`{"title":"一级标题原文","sourceRef":"section-id"}`。所有必需章节必须原样出现在目录中；不得遗漏、擅自合并或重命名。

## 3. 原文与数字保真

- 禁止为了修复代码语法、JSON解析或命令行转义，替换、删除或规范化用户原文中的引号、书名号、标点、换行、数字和特殊字符。
- 禁止未经允许四舍五入、改写单位、缩写机构名称或把否定、退出、延期、风险等表述改为中性表述。
- JSON 必须直接序列化数据。例如 Python 使用 `json.dump(..., ensure_ascii=False)`，JavaScript 使用 `JSON.stringify(...)`。
- 设计上的强调可以改变颜色或粗细，但可见文字必须与源内容一致。

## 4. 表格结构保真

- 源文档已经包含表格时，直接沿用原表的行列方向、表头层级、分组关系和字段顺序；只允许调整列宽、行高、颜色和分页，不得重新建模、转置或把分组表头压成普通表头。
- 提取源表时确认正文行数、逻辑列数、多级表头、行表头列数、合并单元格、最左侧字段和单元格原文。
- 禁止为适应页面而删除最左列、序号列、分类列、单位列或任何其他字段。
- 简单表头使用 `headers`；多级表头使用 `headerRows`。合并单元格使用单元格对象的 `rowspan`、`colspan`。
- `colWidths` 必须为每个逻辑列提供一个正数宽度；初次绘制按已确认布局设置，不得在前期以“单元格不超过2行”反推或阻断列宽。成品阶段的列宽再分配按[成品表格单元格行数优化](#成品表格单元格行数优化)执行。
- `sourceManifest.tables` 对每张表至少记录：`bodyRows`、`logicalColumns`、`headerRowCount`、`rowHeaderColumns`、`headerRowsData`和`bodyRowsData`。单元格对象保留`text`、`rowspan`和`colspan`；不得只记录总行列数。
- 输出中的每个表格块必须声明`sourceRef`、`orientation: "source"`和`rowHeaderColumns`。审计逐项比较表头文字及跨行/跨列关系、正文二维矩阵、行表头字段和单元格顺序；仅总行列数相同不视为通过。
- 同一源表因分页或左右分段产生多个表格块时，只能按正文行顺序切分；每段必须重复完全相同的多级表头和全部逻辑列。禁止按列拆散源表。
- 发现表头层数减少、父表头下的子表头消失、数据被上移吞并、行列互换或字段顺序变化，均按内容丢失处理并停止生成。

## 5. 容量和拆分

- 正文和表格的实际显示字号不得低于10号。禁止用自动缩小字号掩盖内容过量。
- 先根据列宽、文字换行和1.3倍行距估算每一行所需高度，再绘制表格。
- 默认不拆分表格、模块或页面，也不得因模板、模块数量或自动网格改变源阅读方向。`preferredFlow: "single-column"`时必须保持单列。
- 先依次尝试调整模块宽高、改为通栏或单列、让表格独占一行、压缩非内容留白，再将适合的长表按正文行拆成2个或3个左右分段；各段重复完整表头和全部列。把尝试写入`capacityEvidence.singlePageAttempts`。
- 单页方案仍失败时设置`capacityStatus: "warning-pending"`并暂停，向用户说明预计越界位置和已尝试方案，询问是否同意拆页。
- 用户同意拆页后设置`allowSlideSplit: true`和`capacityStatus: "split-approved"`，记录容量证据、`splitReason`、`splitApprovalRef`、页面`approvalRef`及连续页序号；连续页保留全部列、重复表头并标明“续”。
- 用户坚持不拆页时设置`capacityStatus: "user-confirmed-no-split"`、`overflowPolicy: "warn-and-proceed"`和`overflowApprovalRef`。停止用预估越界阻断生成，但该授权不放宽内容保真、表格结构、媒体或文件有效性检查。
- 始终禁止通过裁切、遮盖、删除数据或缩小字号换取通过。

## 6. 媒体保真

- 对源文件中的图片、截图和数据图建立媒体清单，并放到对应内容模块。
- 缩放时保持原始比例，不改变图内文字、裁掉图例或用概括性文字替代原图。
- 生成前检查每个必需媒体 `id` 是否被 image 内容块引用；未使用的必需媒体视为错误。

## 7. 验收状态

验收分三层：

1. 内容审计：源文字、表格行列、媒体和 `sourceRef` 完整。
2. 结构审计：PPTX ZIP/OOXML、页数、页面关系和对象边界正常。
3. 视觉审计：全部页面渲染后逐页检查文字、表格、图片、边框、留白和可读性。

三层全部通过后才能声明任务完成。若缺少可用渲染器，只能报告“结构与内容审计通过，视觉验收未完成”，不得等同于完整交付。用户明确坚持不拆页且制作后仅剩边界问题时，可报告“文件已生成，边界问题待用户决定”，不能报告完整通过。

内容审计还应执行[结构化表达.md](./结构化表达.md)中的退化检查：内容页须包含指标、表格、图表、图片、事项矩阵或提示块等结构化证据；明显的“标签：说明”长列表必须改为矩阵/表格，或填写可核验的纯文字例外理由。

结构审计中的“对象外框未越过页面”不代表视觉边界通过。表格还必须检查OOXML各行高度之和是否超出表格框、模块框或页面；使用形状模拟的表格必须依靠全页渲染检查最后一行和模块底边。报告中应分别给出“对象外框边界”和“表格实际渲染边界”，不得用前者替代后者。

### 成品页面结构与确认大纲一致性检查

- 用户第一次确认大纲时保存不可覆盖的初始快照和`initialApprovalRef`。快照逐页记录页面类型、标题、顺序、`contentGroupRef`、`layoutFlow`以及模块数量、顺序和标题。
- 用户之后在任务中明确提出增页、删页、合并、拆分、换序、改标题、调整模块归属或阅读流时，记录`instructionRef`并保存修改后的完整有效快照。只更新用户明确涉及的结构，其余页面继续继承此前确认结果；生成过程中的临时排版、容量估算或自动布局不得视为用户修改意见。表述不明确时先询问用户，不得自行扩大修改范围。
- 最终检查时从成品文件及其全页渲染结果建立`finalStructureManifest`，逐页比较有效确认大纲中的页面数量、页面顺序、页面类型、标题、内容组、阅读流以及模块数量、顺序和标题。拆页、连续页或结构重组只有能追溯到用户修改依据或既有拆页授权时才允许存在。
- 任一无授权差异均为结构硬错误。按照有效确认大纲恢复受影响页面，再重新执行内容、结构和视觉验收；不得把已生成但错误的页面结构反向写成新大纲，也不得要求用户接受系统自行产生的变化。
- 使用内置脚本时，在输入JSON中填写`confirmedOutline.initialPages`和`initialApprovalRef`；后续明确修改依次写入`confirmedOutline.revisions[]`，每项包含`instructionRef`和修改后的完整`effectivePages`。审计以最后一个有效修改快照为准；没有修改时以初始快照为准。

### 成品表格单元格行数优化

- 本项只在初次文件生成完成并把全部页面渲染为图片后执行。不得把“单元格不超过2行”加入大纲容量估算、生成前审计、初次布局选择或初次绘制阻断。
- 逐表检查所有表头和正文单元格的实际换行，以每个单元格不超过2行为优选目标；达到3行及以上的单元格进入列宽优化。
- 在询问用户前，先缩窄内容较少且存在宽度余量的列，同时增加长文本或高内容量单元格所在列的宽度，使每行可容纳的文字尽可能增加。必须保留全部逻辑列、字段顺序、多级表头、原文和不低于10号的字号，不得用删字、隐藏字段、转置或压缩字号解决。
- 调整列宽后重新生成并渲染受影响页面，再次核对单元格行数、表格总高度、模块边界和页面边界。
- 合理重新分配列宽后仍有3行及以上单元格，但内容完整、可读且没有截断、遮挡或越界时，不把它判为内容或结构硬错误；向用户提供当前文件或受影响页面图片，并列出页码、表格、列、单元格及已尝试的列宽调整，询问用户选择继续调整布局、拆分内容或接受当前效果。用户决定前不得擅自拆页或改变已确认大纲。
- 如果3行及以上同时造成文字截断、不可读遮挡或未经授权的边界越界，仍按既有硬错误和边界规则处理，不能以“等待用户决定”豁免。

### 成品页面与模块留白协调检查

- 本项只在初次文件生成、全页渲染和成品表格单元格行数优化完成后执行。不得把本项的比例阈值用于大纲容量估算、生成前审计、初次布局选择或初次绘制阻断。
- 对每张内容页划定有效内容区，排除固定页边距、页面标题区、Logo、页码和必要安全间距。首页、目录页、章节标题页和结束页允许按既定版式保留大面积留白，不套用内容页的高密度阈值。
- 基于渲染结果记录以下指标：`pageWhitespaceRatio`为有效内容区内未被内容或模块占用的面积比例；`moduleWhitespaceRatio`为模块内容区扣除文字、表格、图表、图片等实际所需包围面积后的比例；`moduleAreaShare`为该模块面积占本页全部模块面积之比；`informationDemandShare`为该模块在保留原文、字号、行距和媒体比例时的内容所需面积占全页各模块内容所需面积之比。
- 模块内部包含多个子模块、表格、图表或独立内容块时，把每个可分辨子区域视为同级模块重复计算内部留白和面积—信息需求关系；不得用模块整体的平均密度掩盖“局部拥挤、局部大片空白”。纯装饰背景、线条和固定标识不计入信息需求。
- 将以下情况标记为布局不协调候选：内容页`pageWhitespaceRatio`超过30%，或存在超过有效内容区15%的连续空白区域；任一模块`moduleWhitespaceRatio`超过35%；同级相邻模块的内部留白比例相差超过20个百分点；模块的`moduleAreaShare / informationDemandShare`小于0.67或大于1.50。阈值用于定位问题，不得脱离渲染画面单独判定；有明确视觉或语义用途的留白应记录理由。
- 尤其检查同页或同一模块内“部分内容已经非常紧凑、另一部分仍有大片空白”的组合。若高密度区域出现多行拥挤、表格过高或元素间距不足，同时低密度区域触发上述留白候选，则必须进入重新布局，不得仅因所有对象都未越界而通过。
- 重新布局时依次尝试：压缩无语义作用的外部空隙并调整摆放位置；缩小低信息密度模块的宽度或高度；把释放的面积分配给高信息密度模块；在不改变已确认阅读顺序、并列或递进关系和`preferredFlow`的前提下重新组织同页行列。不得删减或改写内容、缩小至10号以下、裁切媒体、破坏表格结构或擅自拆页。
- 每轮调整后重新生成并渲染受影响页面，重新计算四项指标，同时检查边界、对齐、阅读顺序和内容完整性。只有未再出现无理由的大面积留白或显著密度失衡，或者已记录合理的版式例外，才可通过视觉验收。
- 如果不改变已确认大纲或不拆页就无法消除显著失衡，向用户提供当前文件或受影响页面图片、四项比例、问题位置及已尝试的布局调整，询问用户选择改变布局关系、拆页或接受当前效果；用户决定前不得擅自改变大纲或拆页。
