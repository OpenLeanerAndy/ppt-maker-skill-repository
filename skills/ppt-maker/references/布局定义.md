# 布局定义的规则与步骤

## 布局定义的步骤
1. 根据主题确定每一页的页面类型
2. 根据每一页的页面类型，和该页内的子标题数量，选择布局方式
3. 根据每一页的布局方式和子标题数量，安排每个子标题的位置
4. 填充每一页的内容
5. 检查内容布局，保证每一部分的内容都能够被正常显示（无遮挡、变形等异常情况）
6. 保存生成给用户的文件
    - 若文件已创建，不需要另存为，直接在原文件保存即可
    - 若文件尚未保存过，则按照[SKILL.md](../SKILL.md)中约定的方式保存

## 布局定义的原则
1. 本Skill为企业商业应用，要求每页的信息量充足、详细、准确、高密度。在每一页总述的观点/结论清晰明确的前提下，尽可能把说明/印证该观点/结论的内容全部放入对应结论的一页内。
2. 绝对禁止使用海报、信息卡等低信息量方式组织页面。
3. 使用章节标题，或者主要结论、观点作为每一页的标题，每一页的内容采用总-分形式组织，每个分内容独立为一个页内的模块。
4. 内容尽可能准确、完整、原文呈现，尽量不要压缩、简化、提炼。
5. 用户提供的原文档中出现的数据表、数据图、图片，需要原样展示在对应页面的对应模块。文字中的关键数据可以原文显示，也可以只作为数据图、数据表、指标卡等形式。
6. 布局必须服从内容保真和可读性；容量评估、单页重排、拆页授权和不拆页例外统一执行[内容保真与验收.md](./内容保真与验收.md#5-容量和拆分)。
7. 整体采用**内容驱动的复合布局**，根据内容调整位置、宽度、高度，不要机械复刻某一张模板页。同页模块内容量不同时，使用不同宽度或高度；不得机械等分后留下大块空白并挤压高密度模块。
8. 切记，评价布局好坏的标准是：
    - 内容量：绝对丰富、充分、详细的内容量
    - 准确性：关键内容原样呈现（不压缩不提炼），数据图、数据表、图片原样呈现
    - 完整度：页面所有内容都能完整、清晰呈现，内容之间没有相互遮盖、显示不全等问题
    - 集中度：每一页逻辑严谨，页内内容充分证明该页主题的观点或结论
9. 页面布局必须落实[结构化表达.md](./结构化表达.md)中确认的内容关系。同一页可采用“指标组 + 异常提示 + 明细表”“指标组 + 结论提示 + 事项矩阵”等复合布局；禁止把所有模块统一降级为标题下的一段项目符号。
10. 保持源文档的阅读方向和语义分组。连续纵向出现、属于同一标题或同一工作流的内容默认采用单列纵向阅读；只有源内容明确为并列关系，或大纲已确认多列对照时，才允许分列。
11. 同一语义组默认在一页内完成。不能因为模板、默认网格或模块数量自动拆页；只有容量估算证明单页无法以10号字完整展示，并完成大纲确认后，才允许使用连续页。

## 页面类型
按照页面的内容和作用，页面可以分为如下类型：
    - 首页：PPT的总标题页，通常是PPT的第一页，用于展示该汇报的总标题
    - 目录页：用于罗列PPT的主干汇报逻辑，通常只罗列一级标题，放在首页后
    - 章节标题页：作用与首页类似，用于展示接下来要汇报的一级标题
    - 内容页：展示具体内容的页面，通常每个页面用来陈述一个观点或结论
    - 结束页：PPT的结尾页，通常用于表达感谢，或使用口号/寄语等形式鼓励用户

## 页面布局方式
以下通过文字形式描述各个页面的布局方式，除文字描述外，还可对照参考[样例.pptx](../assets/样例.pptx)和[模板.pptx](../assets/模板.pptx)。

1. 首页布局
    - 适用页面：首页
    - 布局要求：
        - Logo([logo.png](../assets/logo.png))位于右上方，尺寸明显大于正文页 Logo。图片宽度为 8.66 厘米，长宽比保持与原图一致。
        - 主标题水平居中，位于页面中上部。如超过15个字，则拆为两行，按照语义完整性拆解，不要从词或短语中间拆。
        - 页面左侧约 1.65 英寸处有一组细蓝色双竖线，上端起点与标题文字所在文本框的上边缘齐平，下端终点与下方部门、日期所在文本框的边缘齐平。即标题、部门、日期的文字内容都在双竖线的覆盖范围内。
        - 部门与日期位于主标题下方，整体居中排列，与标题保持至少2行距离。
        - 页面保持大面积白色，除上述已说明的元素外，页面内不再增加其他元素。
    - 全页布局效果参考([首页样例.png](../assets/samples/首页样例.png))。

2. 目录页布局
    - 适用页面：目录页
    - 布局要求：
        - 左上方使用深蓝色“目录”二字，字号至少为“页面标题”字号。
        - “目录”文字下方放置蓝色渐变分隔线，贯穿页面大部分宽度，左侧起点与目“目录”的文本框的左边缘齐平。左侧为深蓝色，右侧为浅蓝色。
        - 渐变分割线右侧放置Logo([logo.png](../assets/logo.png))，图片宽度为 5.3 厘米，长宽比保持与原图一致。
        - 章节列表位于页面中部偏右，不做满页铺陈。
        - 每个章节前使用中文数字序号（如“一、”、“二、”）。当前章节为黑色，非当前章节为浅灰色。
        - 页面保持大面积白色，除上述已说明的元素外，页面内不再增加其他元素。

3. 章节标题页布局
    - 适用页面：章节标题页
    - 布局要求：
        - 复制目录页，并将接下来要展开的部分改为“当前章节”的黑色展示，将其它章节都改为“非当前章节”的浅灰色展示。
        - 除以上要求外，不要添加、删减、改变其他元素。

4. 项目总述布局-1
    - 适用页面：内容页
    - 适用内容：项目总述内容，如项目目标总述或项目总结总述等。页面包含总目标、主要的子项目拆解与子项目目标、子目标细节表、进度细节表等元素。通常作为正文内容的第一页。
    - 布局要求：
        - 页面不做纵向分栏，横贯宽度分为上、中、下三部分。
        - 上部放置总述（通常为一句话，最多不超过2行），文字前方放置蓝色方形项目符号。
        - 中部放置子目标说明（分项说明），形成总目标到分项目标拆解的逻辑，如模板页中的“核心价值、组织效率、团队能力、统筹牵引”四个指标。每个指标前放置蓝色圆形项目符号。
        - 下部放置具体的细节表格，如子目标细节表、进度细节表等。本部分如有多个表格，可从左到右按逻辑放置。
            - 如页面内容是立项总述或目标总述（即项目处于计划阶段，尚未正式启动），则多张列表可能是目标、当前情况、措施/任务/动作等。按照先分析差距，再具体阐述执行方式的逻辑排列。该逻辑可做参考，具体根据用户提供的原文档内容确定。
            - 如页面内容是项目总结总述（即项目已经执行完毕），则多张表格可能是目标、最终情况、完成度、原因、下一步动作等。按照先看结果，再分析差异找原因，再规划下一步动作的逻辑排列。该逻辑可做参考，具体根据用户提供的原文档内容确定。
            - 如页面内容是项目中期汇报（即项目已经进行了部分工作），则多张表格可能是目标、当前数据情况、完成度、原因、下一步动作等。按照先看结果，再分析未完成项的原因，再规划下一步动作的逻辑排列。该逻辑可做参考，具体根据用户提供的原文档内容确定。
    - 布局效果参考：([项目总述布局样例.png](../assets/samples/项目总述布局样例.png))

5. 项目总述布局-2
    - 适用页面：内容页
    - 适用内容：项目总述内容，如项目的总目标/总任务、项目组成部分的架构、项目的关键任务、项目支撑因素等。
    - 布局要求：
        - 页面总体分为上下两部分，上部分通栏放置项目的整体目标、整体结论等顶层、提纲挈领、高度概括的重要表述。通常为一句话，最多不超过2行。
        - 下部分模块放置“关键子目标”、“关键任务”、“项目组成部分”、“项目支撑因素”等隶属于整体目标或整体结论的下级版块的内容。
            - 每个模块都要突出关键信息，让用户一眼能看到该模块的重点信息。
            - 具体的模块设置与内容，根据用户提供的原文档确定。
            - 根据模块的内容、逻辑与内容量，下部分的模块可以布局为1-2行，每行还可以再分成1-4列；同样也可以布局为1-3列，每列再分成1-2行。每行或每列的高度或宽度根据内容量决定，无需固定。
            - 要求所有展示的内容都能完整展示，相互之间不被遮挡。
    - 布局效果参考：([项目总述布局样例-2.png](../assets/samples/项目总述布局样例-2.png))
        - 这个页面的内容区域整体分成上下两部分，上部分通栏使用蓝色边框，放置总体观点或结论。
        - 下部分整体分成两列，其中左侧列分成上下两行。左侧列上行放置目标拆解的4个关键任务，使用蓝色虚线边框包围。左侧列下行分左右两列展示两个关键任务（“提升组织效率”和“提升团队能力”），使用带蓝色背景+蓝色边框的矩形框样式，内部再放置正文。右侧列不分行，展示“强化统筹牵引”和“考核牵引”的保证条件。
        - 整体页面布局版块清晰，位置协调合理。

6. 总-分布局
    - 适用页面：内容页
    - 适用内容：各章节的具体展开内容，先明确指出观点或结论，再通过多个具体的数据、案例等具体说明和证明。
    - 布局要求：
        - 页面总体分为上下两部分，上部分通栏放置该部分内容的总体观点或结论，作为总述。通常用通栏设计，每部部分分列。
        - 下部分为具体的二级标题+内容，甚至还可再分为三级标题+内容。根据各版块的关系，可以调整布局为：
            - 一行多列的形式：
                - 列的高度直接通到页面底部，每列对应一个子标题。
                - 每列内部放置内容，如文字、关键数字、指标卡、数据图、数据表、图片等。还可以再分成孙标题及其关键内容，在列内上下排列。
                - 页内所有同级别的标题使用相同的字体、字号、对齐方式与修饰方式。不同级别的标题要有明显的显示差别。
                - 页内所有同级别的内容使用相同的字体、字号、对齐方式与修饰方式。
                - 各列的高度相同，宽度通常相同，也可根据内容灵活调整。要保证内容完整显示且不被遮挡。
                - 通常总述内容下方包含多个并列或递进关系的子标题时，可以使用此形式。
            - 多行一列的形式：
                - 行的宽度直通页面右侧，每行对应一个子标题。
                - 每行内部放置内容，如文字、关键数字、指标卡、数据图、数据表、图片等。
                - 页内所有同级别的标题使用相同的字体、字号、对齐方式与修饰方式。不同级别的标题要有明显的显示差别。
                - 页内所有同级别的内容使用相同的字体、字号、对齐方式与修饰方式。
                - 各行的宽度相同，高度通常相同，也可根据内容灵活调整。要保证内容完整显示且不被遮挡。
                - 通常总述内容包含多个步骤（时间先后顺序），或包含带有递进关系的子标题时，可以使用此形式。
            - 两列+列内多行的形式：
                - 页面整体分成左右两列，每列可只放置一个版块，也可再细分多行，放置多个板块，具体根据用户提供的原文档的内容确定。
                - 每个版块都要有自己的标题和内容，内容包括如文字、关键数字、指标卡、数据图、数据表、图片等。
                - 页内所有同级别的标题使用相同的字体、字号、对齐方式与修饰方式。不同级别的标题要有明显的显示差别。
                - 页内所有同级别的内容使用相同的字体、字号、对齐方式与修饰方式。
                - 两列的宽度可以不同，根据内部的内容量灵活调整。但要保证同一列内部模块的宽度一致，且所有内容完整显示且不被遮挡。
                - 布局效果参考：([2列+列内多行样例-1.png](../assets/samples/2列+列内多行样例-1.png))、([2列+列内多行样例-2.png](../assets/samples/2列+列内多行样例-2.png))
            - 两行+行内多列的形式：
                - 页面整体分成上下两行，每行可只放置一个版块，也可再细分多列，放置多个板块，具体根据用户提供的原文档的内容确定。
                - 每个版块都要有自己的标题和内容，内容包括如文字、关键数字、指标卡、数据图、数据表、图片等。
                - 页内所有同级别的标题使用相同的字体、字号、对齐方式与修饰方式。不同级别的标题要有明显的显示差别。
                - 页内所有同级别的内容使用相同的字体、字号、对齐方式与修饰方式。
                - 两行的高度可以不同，根据内部的内容量灵活调整。但要保证同一行内部模块的宽度一致，且所有内容完整显示且不被遮挡。
                - 布局效果参考：([2行+行内多列样例-1.png](../assets/samples/2行+行内多列样例-1.png))、([2行+行内多列样例-2.png](../assets/samples/2行+行内多列样例-2.png))

7. 全表布局
    - 适用页面：内容页
    - 适用内容：用含有多行多列的表格传递完整信息，通常表格占据整个内容区；一页无法清晰显示时必须按本节规则拆分。
    - 布局要求：
        - 表格平铺到全页的内容区展示。
        - 行表头、列表头均需按照[风格定义规则](./风格定义.md)的要求设计，需要注意表头有多行或多列的情况。
        - 表格的列宽、行高根据内容灵活调整，尽量保持同一行所有单元格的内容行数相同（或最多相差1）。
        - 表格结构核对、行高估算、同页分段和拆页决策统一执行[内容保真与验收.md](./内容保真与验收.md#4-表格结构保真)中的表格规则及“容量和拆分”规则。
        - 表格外框、最后一行和最右列必须完整位于所属模块内容区内，并与模块底边、页码区保持安全间距；边界检查同时使用对象外框和各行实际高度之和。

## 单页内模块的内部布局方式
- 适用页面：内容页
- 适用情况：在总-分结构的各分模块内容，通常还会分成更下级的模块，并在更下级的模块中同样包含总-分结构。本部分用于定义分模块内部有更下级模块的布局方式。
- 布局要求：
    - 所有分模块仍旧都包括标题和内容（文字、数据表、数据图、图片、指标卡等）。
    - 模块的行列排列必须来自大纲中的`preferredFlow`和并列/递进关系。未声明多列关系时使用单列，不得按模块数量自动生成多列网格。
    - 所有分模块的同级标题使用相同的样式展示（含字体、字号、居中方式、修饰方式等）。
    - 模块内表格的通栏、2—3段左右排列和拆页处理执行[内容保真与验收.md](./内容保真与验收.md#5-容量和拆分)；视觉形式可参考[2行+行内多列样例-2](../assets/samples/2行+行内多列样例-2.png)。
    - 模块中如包括多个数据表、数据图、图片、指标卡等元素，则分行展示，同一行可从左到右展示多个元素。如：[2列+列内多行样例-2.png](../assets/samples/2列+列内多行样例-2.png)中右侧列第一行模块内的多个指标卡 及 右侧列第四行模块内的多个指标卡和柱状图 所示。
    - 模块内有3项及以上“事项名 + 说明”的并列内容时，采用2–4列的事项矩阵；每个子项有独立标题和正文。同一模块内的子项样式一致，列数根据内容长度决定。
    - 行动计划按业务板块划分一级模块，再在模块内按任务名称拆成子项；任务多的模块应获得更大宽度或高度，禁止机械三等分。
    - 关键数字、结论、异常和明细同时存在时，按阅读顺序纵向组织：先指标组，再结论/异常提示，最后明细表或事项矩阵。
